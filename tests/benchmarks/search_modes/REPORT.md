# Search modes benchmark (Scenario 1 data)

Generated by `run.py` (no chat LLM). `search(limit=100, node_types=["Fact"])` per system.
Question sets: **S1** = 40 Scenario 1 questions (chain2/chain3/aggregate/current/control); **typo** = 16 core facts queried with one character transposition in every capitalised word; **ident** = 12 bare ticket ids (`OPS-48200`) with a one-digit-apart twin fact in the graph.
Metrics: MRR of first gold fact, R@5 = share of gold in top 5, rec@1k = share of gold within 1000 tokens (regex token proxy), tok = median tokens until all gold seen, lat = median ms per call (warm index; includes the shared post-processing DB queries).

## Reading

- Embedding stays the best single mode on natural-language questions; BM25/fuzzy lose ~0.1-0.17 MRR as noise grows.
- Fuzzy fixes typos (typo MRR 1.0 vs BM25 ~0.4) at the same S1 quality as BM25.
- `hybrid(emb+bm25)` is close to embedding on S1 (equal or better at 10k on FalkorDB) and much better than BM25 on typos; adding fuzzy to the fusion makes typo MRR ~0.97-1.0 for a small S1 cost.
- `exact` returns nothing for questions (they are not substrings of facts) and is meant for identifiers/quoted phrases; it is perfect on ident.
- The ident probe is saturated: every mode gets MRR 1.0, so it does not separate modes here.
- The reranker with pure CE order (`replace`; what these DB tables measured) lifts S1 MRR to 1.0/0.988 but **hurts typo queries** (0.64→0.32 as noise grows) and adds ~200-250 ms (FalkorDB) per call; recall@budget and R@5 are unchanged because it only reorders top 30.
- Embedding latency on this box (CPU, e5-base) dominates; lexical scoring itself is <5 ms at 10k, the rest is shared post-processing queries.
- See **Offline reranker strategies** below for `gated` / `rrf` / `protect` comparisons (no DB). Recommended opt-in strategy is `gated`; production defaults stay embedding + rerank off.

## Offline reranker strategies (no graph DB)

Label: **offline evaluation** — candidate retrieval uses the local embedding
model and in-memory BM25 over fact texts only (core + 1000 noise + ident
facts = 1116 passages). Not a FalkorDB/ArcadeDB run; latency is therefore
not comparable to the tables above (no shared post-processing DB queries).

Script: `rerank_offline.py`. Model: `Xenova/ms-marco-MiniLM-L-6-v2` (~90 MB

### Strategy reading

- **Primary criterion** = ordinary / agent-generated queries (S1 + holdout +
  agent). Typos are secondary.
- `replace` (pure CE) lifts S1/holdout MRR to 1.0 but collapses typo MRR
  (~0.44), matching the earlier DB finding.
- `rrf` / `protect` soften the typo hit but do **not** improve S1 over the
  first-stage baseline on this set.
- `gated` (default when reranking): apply CE order only when top-1 vs top-2
  CE logits differ by ≥ `SEARCH_RERANK_GATE_MARGIN` (2.0); else keep the
  first-stage order. On embedding candidates it matches `replace` on S1
  (1.0) while keeping typo MRR 1.0. On hybrid candidates S1 reaches 1.0 and
  typo stays at the hybrid baseline (0.906).
- R@5 is unchanged for all strategies (reorder within top 30).
- Russian probes stay weak (~0.3): the CE is English MS MARCO. Practical
  multilingual CE ONNX weights (bge-reranker-base / v2-m3) are hundreds of
  MB to >1 GB and were **not** downloaded. Prefer the multilingual e5
  embedding first-stage for RU/EN; gated does not make RU worse than the
  baseline.
- Margin 2.0 was selected on this corpus (also checked on first/second half
  S1 splits and weighted-RRF/blend sweeps). Treat as a starting point, not
  a guarantee on other workloads.
- **Defaults unchanged for production path:** `SEARCH_MODE=embedding`,
  `SEARCH_RERANKER=false`. When opting into rerank, `SEARCH_RERANK_STRATEGY`
  defaults to `gated`. Confirm on a live store when Docker is available;
  previous DB tables used pure CE (`replace` behaviour).

## Rerank speed experiments (offline, no graph DB)

Box: 8 vCPU, CPU only, shared with other agents (load average 7–17 during the
latency run, so absolute numbers are noisy). Model `Xenova/ms-marco-MiniLM-L-6-v2`
ONNX fp32; embedding `intfloat/multilingual-e5-base`. Corpus: 107 core + 24
ident + 1000 noise facts. Not comparable to the DB tables above.
Scripts: `rerank_profile.py`, `rerank_sweep.py`, `rerank_latency.py`.

Note: `gated` decides *after* CE scoring, so it does not save inference. Savings
come from a smaller pool (`SEARCH_RERANK_TOP_K`) or the new pre-inference skip.

### CE-only cost (40 S1 queries × 3, warm, median / p95 ms)

Cold model load ~1.0 s, first inference ~93 ms. Query+fact pairs are ~31
tokens, so `_MAX_LEN=256` truncation is not a cost factor (no change made).

| pool K | 2 threads | 4 threads | 8 threads |
|---|---|---|---|
| 5 | 10.3 / 13.0 | 6.7 / 8.4 | 6.0 / 11.3 |
| 10 | 17.2 / 23.6 | 11.7 / 13.7 | 10.1 / 16.6 |
| 20 | 31.3 / 40.7 | 19.1 / 25.9 | 17.3 / 27.9 |
| 30 | 51.4 / 66.6 | 29.5 / 35.2 | 23.7 / 33.9 |

### End-to-end (query embedding + top-100 + rerank; 40 queries × 3 warm, n=120)

| config | median ms | p95 ms |
|---|---|---|
| rerank off | 56.1 | 96.0 |
| gated K=30, 2 threads (previous) | 153.2 | 185.9 |
| gated K=10, 2 threads | 112.1 | 157.1 |
| gated K=10, 4 threads | 124.8 | 161.2 |
| gated K=10, 2 threads, skip gap 0.02 | 94.1 | 148.0 |
| gated K=10, 4 threads, skip gap 0.02 | 110.2 | 164.7 |

Under the concurrent load, 4 threads were not faster end to end even though
CE-only timing was; default stays 2 (`SEARCH_RERANKER_THREADS`).

### Quality (MRR; embedding first stage, gated margin 2.0)

Sets: S1 40, holdout 20 (odd ids), agent 12, typo 16, ident 12, ru 8.
Baseline (no rerank): S1 0.988, holdout 0.975, agent 1.0, typo 1.0, ident 1.0, ru 0.597.
Every K in {5,10,20,30} and skip gap in {off, 0.02, 0.04}: S1 1.0, holdout 1.0,
agent 1.0, typo 1.0, ident 1.0, ru 0.597. Skip 0.02 avoided CE on 58/108 queries,
0.04 on 15/108.

**Limitation:** this set is saturated, so it cannot separate K=10 from K=30 or show
the risk of skipping. Distractors are template facts with shared names/teams
(the hardest available here); there are no real-world agent queries. The gold fact
is almost always already in the embedding top 5, which favours small K.

### Recommendation

- New options, defaults unchanged: `SEARCH_RERANKER_THREADS=2`,
  `SEARCH_RERANK_SKIP_SIM_GAP=0` (off). `SEARCH_RERANK_TOP_K` stayed 30 at that point (changed to 10 below).
- If rerank is enabled, try `SEARCH_RERANK_TOP_K=10` (~27% lower median here, no
  quality loss measured). `SEARCH_RERANK_SKIP_SIM_GAP=0.02` cut the median by
  another ~16%, but it is a heuristic tuned on this corpus; enable it only after
  a check on real data.
- Smaller pools reorder only the head; the remaining candidates keep their order
  and are never dropped (unit tested). Skip applies only when results carry
  embedding `similarity` (embedding mode; hybrid/lexical never skip).

## Selected rerank config: top 10 (offline, no graph DB)

Chosen after the speed experiments: when rerank is enabled, defaults are
`SEARCH_RERANK_TOP_K=10`, `SEARCH_RERANK_STRATEGY=gated`, `SEARCH_RERANKER_THREADS=2`,
`SEARCH_RERANK_SKIP_SIM_GAP=0`. Global defaults unchanged: `SEARCH_RERANKER=false`,
`SEARCH_MODE=embedding`. The rerank pool no longer grows with `limit`
(previously `max(limit, top_k)`); results beyond the first 10 keep first-stage order.

Script `rerank_top10.py`; same corpus as above (1131 facts); embedding top 100;
2 warm passes × 88 queries = 176 timed calls; box load average ~14 on 8 vCPU.
